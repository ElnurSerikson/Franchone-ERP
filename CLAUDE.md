# Правила работы над FRANCHONE ERP

## Главное правило: пуш после каждой правки, не спрашивая

**Закончил правку — сразу `git commit` и `git push origin main`.** Разрешения не спрашивать, паузу «сделать пуш?» не брать. Владелец итерирует мелкими правками и смотрит результат сразу на erp.franchone.kz.

Исключения: не пушить заведомо сломанное и не забирать в коммит чужую незакоммиченную работу — класть только свои файлы, по именам.

## Вся разработка — локально, на dev-среде

Работаем и проверяем только локально:

```bash
npx convex dev     # бэкенд → dev-деплоймент affable-kookabura-929
npm run dev        # фронт → http://localhost:5173
```

`.env.local` уже настроен на dev-деплоймент. Ломать на dev можно что угодно: схему, данные, функции — прод изолирован, пользователи ничего не замечают.

## Опасные команды — не запускать

- **`npx convex deploy`** — выкатывает в **ПРОД** (`dependable-mallard-5`), а не в dev. Никогда не запускать без прямой команды.
- **`npx convex dev --once`** — это dev, безопасно.

## Как код попадает в прод

Только так: `git push origin main` → Vercel запускает `npx convex deploy --cmd 'npm run build'` → бэкенд и фронт уезжают в прод одной операцией. Ручных шагов больше нет.

## Перед тем как сказать «готово»

Прогнать `npx tsc --noEmit` и `npm run build` — чтобы не выкатить сломанное, — закоммитить, запушить и отчитаться о результате.
