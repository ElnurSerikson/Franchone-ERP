# Правила работы над FRANCHONE ERP

## Главное правило: никаких пушей без команды

**`git push` — только по прямой команде владельца.** Не «я закончил, значит можно», не «изменение маленькое», не «чтобы не потерялось». Пока владелец не сказал «пуш» — код остаётся на локальной машине.

Причина: пуш в `main` мгновенно выкатывает и фронт, и бэкенд боевым пользователям. Владелец сам решает, когда он доволен результатом.

То же касается `git commit` — делать только когда попросили.

## Вся разработка — локально, на dev-среде

Работаем и проверяем только локально:

```bash
npx convex dev     # бэкенд → dev-деплоймент affable-kookabura-929
npm run dev        # фронт → http://localhost:5173
```

`.env.local` уже настроен на dev-деплоймент. Ломать на dev можно что угодно: схему, данные, функции — прод изолирован, пользователи ничего не замечают.

## Опасные команды — не запускать

- **`npx convex deploy`** — выкатывает в **ПРОД** (`dependable-mallard-5`), а не в dev. Никогда не запускать без прямой команды.
- **`npx convex dev --once`** — это dev, безопасно.

## Как код попадает в прод

Только так: владелец говорит «пуш» → `git push origin main` → Vercel запускает `npx convex deploy --cmd 'npm run build'` → бэкенд и фронт уезжают в прод одной операцией. Ручных шагов больше нет.

## Перед тем как сказать «готово»

Прогнать `npx tsc --noEmit` и `npm run build`, проверить изменение вживую на localhost. Отчитаться о результате — и ждать команды.
